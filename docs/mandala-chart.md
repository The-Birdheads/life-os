# マンダラチャート機能(企画)

Habitas の次のバージョン(1.4.0 を想定)の目玉機能の企画書です。**たたき台**です。
「ユーザーストーリー」と「機能イメージ(画面の流れ)」をまとめ、決めることを洗い出します。

- ストーリーの書式は [user-stories.md](user-stories.md) に合わせています。新しい領域コードは **MND**(マンダラチャート)です。
- 実装が済んだストーリーは、user-stories.md に移します(ID はそのまま使う)。
- まだ決まっていないことは **(要検討)** と書き、最後の「決めること」に集めています。

---

## 1. ねらい

いまの Habitas は「毎日やること(習慣・タスク・行動)を記録して、一日を振り返る」アプリです。
一方で、**「なぜそれをやるのか(目標)」** を置く場所がありません。

マンダラチャートで目標を分解し、そのマスから習慣・タスクを作れるようにすることで、次の流れを1つのアプリで回せるようにします。

```
 計画                     実行                      振り返り
 ─────────────            ─────────────            ─────────────
 大目標を決める     →     マスから習慣・タスク  →   チャート上で、
 8つの要素に分ける        を作り、毎日記録する      どの目標が進んで
 要素ごとに8つの行動                                いるか色で見る
                                ↑                         │
                                └──── 見直して、マスを書き換える ─┘
```

### マンダラチャートとは
9×9 のマスで目標を分解する手法です。

- 中心のマスに **大目標** を書く(例: 健康的な体をつくる)
- そのまわりの 8 マスに、大目標を達成するための **要素** を書く(例: 食事、睡眠、運動 …)
- 8 つの要素それぞれを中心にした 3×3 をつくり、まわりの 8 マスに **具体的な行動** を書く(例: 夜の間食をやめる)
- 行動は 8 要素 × 8 = 最大 **64 マス**

### この企画での呼び方
| 呼び方 | 内容 | 数 |
|---|---|---|
| チャート | マンダラチャート1枚 | (MVP は同時に1枚。要検討) |
| 大目標 | チャートの中心のマス | 1 |
| 要素 | 大目標のまわりの 8 マス。要素ごとに色を持つ | 8 |
| 行動目標 | 要素のまわりの 8 マス。ここから習慣・タスクを作る | 最大 64 |
| マス | 上のどれか1つ | |
| ひもづけ | 行動目標のマスと、習慣・タスクを結びつけること。ひもづけた日を記録する | 1マスに複数 |
| 見直し | 結果を見て、マスごとに次の手(続ける・ハードルを下げる など)を決め、メモを残すこと。好きなタイミングで行う | |
| 見直しの記録 | 見直しを保存したときに残る「見直す前のチャート・当時の進み具合・決めたこと・メモ」。あとから見返せる | 見直しごとに1つ |

> 既存の「行動」(行動の種類と行動ログ)と、チャートの「行動目標」は別物です。混乱を避けるため、チャート側は「行動目標」と呼びます(名前は要検討)。

## 3. 画面の名前(追加・変更)

| 呼び方 | 内容 |
|---|---|
| 目標タブ | 下のタブに新しく足す「目標」(要検討: 振り返りタブの中に置く案もある)。チャートを表示する |
| チャート(中心) | 目標タブの最初の表示。大目標と8つの要素の 3×3 |
| チャート(要素) | 要素をタップして開く 3×3。要素と8つの行動目標 |
| チャート(全体) | 9×9 をすべて表示する画面。見るだけ(編集は中心・要素の画面で行う) |

| 見直しの履歴 | チャート(中心)の「見直しの履歴」から開く。過去の見直しの一覧と、見直す前のチャート(見るだけ) |

## 4. 機能イメージ(画面の流れ)

スマホの画面では 9×9(81マス)は1マスが小さすぎて読めません。そこで、**3×3 を基本の表示単位**にして、
「中心(大目標+要素)」と「要素(要素+行動目標)」を行き来する作りにします。9×9 は全体を眺める用です。

├──────────────────────────────┤
│                              │

│                              │
│  大きな目標を 8 つの要素と        │
│  64 の行動に分けて、毎日の       │
│  習慣・タスクにつなげます         │

│                      │   │ │食事│睡眠│運動│     │   │ │23時│スマ│朝日│     │
│ いつまでに(任意)       │   │ ├────┼────┼────┤     │   │ │に寝│ホは│を浴│     │
│ [2027/03/31        ▼]│   │ │体重│ 健 │心 │     │   │ ├────┼────┼────┤     │
│                      │   │ │管理│ 康 │   │     │   │ │    │睡眠│    │     │
│                      │   │ ├────┼────┼────┤     │   │ ├────┼────┼────┤     │
│                      │   │ │ 習 │    │    │     │   │ │    │    │    │     │
│                      │   │ │ 慣 │    │    │     │   │ └────┴────┴────┘     │
│                      │   │ └────┴────┴────┘     │   │ ◀ 心   睡眠(2/8)  運動 ▶│
│          [次へ]       │   │  空いたマスはあとで    │   │ [あとで] [完了]        │

- 全部埋めなくても「完了」できる。空いたマスは、あとでチャート上から埋める
- ステップ 3 は要素を左右に切り替えながら入力する

### 4-3. チャート(中心)— 目標タブの基本の画面

```
┌──────────────────────────────┐
│ 健康的な体をつくる   〜2027/3/31 ✎ │
│ 期間: [7日] [30日] [全期間]       │
│ ┌────────┬────────┬────────┐ │
│ │ 食事    │ 睡眠    │ 運動    │ │
│ │ ███░ 72%│ ██░░ 45%│ █░░░ 20%│ │
│ ├────────┼────────┼────────┤ │
│ │ 体重管理│  健康的 │ 心      │ │
│ │ ███░ 68%│  な体を │ ░░░░ ─  │ │
│ │         │  つくる │ 未着手   │ │
│ ├────────┼────────┼────────┤ │
│ │ 習慣化  │ (空き)  │ (空き)  │ │
│ │ ██░░ 50%│  ＋     │  ＋     │ │
│ └────────┴────────┴────────┘ │
│  [全体を見る 9×9]  [見直す]       │
└──────────────────────────────┘
```

- 要素ごとに色を持つ(記録タブのカードにも同じ色で出る)
- マスの濃さ・バーで、その要素の進み具合(4-6 の計算)を表す
- 要素をタップ → チャート(要素)へ。大目標をタップ → マスの詳細(大目標の編集)

### 4-4. チャート(要素)

```
┌──────────────────────────────┐
│ ‹ 中心へ        睡眠        ◀ ▶ │
│ ┌────────┬────────┬────────┐ │
│ │23時に寝る│スマホを │朝日を   │ │
│ │ 🔁習慣   │寝室に   │浴びる   │ │
│ │ 6/7日   │持ち込まない│🔁習慣  │ │
│ │         │🔁 3/7日 │ 1/7日  │ │
│ ├────────┼────────┼────────┤ │
│ │カフェイン│  睡眠   │枕を     │ │
│ │15時まで │         │買い替える│ │
│ │ (未設定)│         │✅タスク │ │
│ │  ＋     │         │ 完了    │ │
│ ├────────┼────────┼────────┤ │
│ │ (空き)  │ (空き)  │ (空き)  │ │
│ │  ＋     │  ＋     │  ＋     │ │

└──────────────────────────────┘
```

- 🔁 は習慣、✅ はタスクがひもづいていることを示す。数字は期間内の実施状況
- 「(未設定)」は、行動目標は書いたが、まだ習慣・タスクを作っていないマス
- ◀ ▶ で隣の要素へ移動する(スワイプでも可)

### 4-5. マスの詳細(下から出るシート)

```
┌──────────────────────────────┐
│ 睡眠 › 23時に寝る          ✎ 🗑 │
├──────────────────────────────┤
│ ひもづいた習慣・タスク             │
│  🔁 23時に布団に入る   6/7日  86% │
│  🔁 22時に照明を落とす 4/7日  57% │
│                              │
│ ┌──────────┐ ┌──────────┐    │
│ │＋習慣を作る│ │＋タスクを作る│    │
│ └──────────┘ └──────────┘    │
│  既存の習慣・タスクをひもづける ›    │
├──────────────────────────────┤
│ 直近30日   ▁▃▅▆▇▆▅▇▆▇ (実施率)    │
└──────────────────────────────┘
```

- 「＋習慣を作る」→ いまの「習慣の登録」の入力欄が、タイトル=マスの文言で開く。保存するとこのマスにひもづく
- 「既存の…」→ 登録済みの習慣・タスクの一覧から選ぶ(1つの習慣・タスクは1マスにだけひもづく)

### 4-6. 進み具合の計算

数える期間は、表示中の期間(直近7日など)のうち、**ひもづけた日以降**だけ。ひもづける前の記録や、終了・休止した習慣は数えない。

| 対象 | 計算 |
|---|---|
| 習慣(毎日) | 完了にした日数 ÷ 期間の日数 |
| 習慣(週n回) | 完了にした回数 ÷ 目標回数(n × 期間の週数)。目標を超えた分は数えない(上限 100%) |
| 習慣(曜日指定) | 予定の曜日に完了にした回数 ÷ 期間内の予定の日数。予定のない日の記録は数えない |
| タスク | 完了なら 100%、未完了なら 0%(期限切れは別の色で示す) |
| 行動目標のマス | ひもづいた習慣・タスクの平均。ひもづけが無いマスは「未着手」で、平均に入れない。**休止中**のマスは平均に入れない。**達成**のマスは 100% |
| 要素のマス | 配下の行動目標のマスの平均 |
| 大目標 | 要素の平均(表示するかは要検討) |

色は 4 段階(未着手 / 〜30% / 〜70% / 70%〜)。数字も添える。

### 4-7. チャート(全体 9×9)

```
┌────┬────┬────┬────┬────┬────┬────┬────┬────┐
│ ▓  │ ▒  │ ░  │    │    │    │    │    │    │
├── 食事 ──┼── 睡眠 ──┼── 運動 ──┤  … (各 3×3 の中心が要素) …
│    │    │    │    │    │    │    │    │    │
└────┴────┴────┴────┴────┴────┴────┴────┴────┘
```

- 文言は小さく、主に **色の濃淡で全体の進み具合を眺める** ための画面
- ピンチで拡大できる。マスをタップすると、その要素の 3×3 へ移動する
- 画像として保存・共有できる(MND-009)

### 4-8. 記録タブとのつながり

```
┌──────────────────────────────┐
│ ☐ 23時に布団に入る                │
│   優先度 3  ▬▬▬░░  30分            │
│   ● 睡眠                         │  ← 要素の色のチップ
└──────────────────────────────┘
```

- ひもづいた習慣・タスクのカードに、要素の名前を色つきの小さなチップで出す
- 「すべて／習慣／タスク／行動」の絞り込みに加えて、要素で絞り込める(MND-014、優先度は低)

### 4-9. チャートの見直し(好きなタイミングで)

チャート(中心)の「見直す」から開く。3つの段階を、1つの画面で上から順に行う。

```
┌──────────────────────────────┐
│ キャンセル   チャートの見直し        │
│ 直近7日の結果と、前回(10/01)との差   │
│ 1. 結果を見る                      │
│  ● 食事      ████░  67%   +12    │
│  ● 運動      █░░░░  26%    −4    │
│  ● メンタル  ███░░  50%   新規    │
│ 2. マスごとに、次の手を決める        │
│  ● 運動 › ジムに週2回行く     0%   │  ← 進み具合の低い順
│     ジムに行く(週2回)              │
│     → やり方を変える               │  ← 決めた手
│  ● 運動 › 1日8000歩あるく    29%   │
│ 3. メモを残す                      │
│  よかったこと   [               ]  │
│  次に変えること [               ]  │
│ [ 見直しを保存する ]                │
└──────────────────────────────┘
```

マスをタップすると、次の手を選ぶシートが出る。

| 次の手 | どういうときか | 習慣・タスクはどうなるか | 進み具合 |
|---|---|---|---|
| **続ける** | 順調、または様子を見たい | 変わらない | 変わらない |
| **ハードルを下げる** | やり方は合っているが、きつい | 同じ習慣のタイトル・頻度を直す(例: 週3回 → 週2回) | 記録はつながったまま |
| **やり方を変える** | このやり方は合わなかった | 今の習慣を終了し(記録は残る)、新しい習慣を作る。マスの文言も直せる | 新しい習慣は作った日から数え直す |
| **いったん休む** | 今は優先しない | 習慣を記録タブから外す(再開できる) | マスを平均から外す |
| **達成にする** | もう意識しなくてもできる | 続けるか、終えるかを選ぶ | マスは 100% |
| **目標から外す** | そもそも要らなかった | ひもづけを外す。習慣は残すか終えるかを選ぶ | マスが空になる |

- **チャートを変えても、習慣・タスクと過去の記録は消さない。** 変わるのは、マスとのつながりと、これから数える範囲だけ
- 見直しの途中で決めた内容は、「保存」したときにまとめてチャート・習慣に反映する(実装時に変更。途中で反映して「キャンセル」で戻すより、取り消しが確実なため)。「キャンセル」すると何も変わらない
- 「保存」すると、**見直す前のチャート・当時の進み具合・決めたこと・メモ** が「見直しの記録」として残る(4-10)
- **達成にする** だけは、見直しを通さずにマスのシートからもできる(実装時に追加。習慣・タスクを作らずにできてしまう行動目標もあるため)。ひもづいた習慣があれば、続けるか終えるかを選ぶ。間違えたときは、マスのシートの「取り消す」で戻せる(終えた習慣は戻らない)
- 変えた内容は、マスの「変更の履歴」にも残る(例: 「11/01 やり方を変えた。『ジムに週2回行く』→『家で筋トレする』。習慣『ジムに行く』を終了、『帰宅後にスクワット10回』(毎日)を開始」)

## 5. ユーザーストーリー

### MND マンダラチャート

#### 計画

### MND-001 大目標を決めて、チャートを作り始める
- **ストーリー**: 目標を立てたい人として、なりたい姿を1つ決めて、チャートの中心に置きたい。それは、日々の行動の「なぜ」をはっきりさせるため。
- **対象**: 目標を立てたい人
- **優先度**: 高　**状態**: 未実装
- **動作の流れ**:
  1. [目標タブ] 「マンダラチャートを作る」をタップ → 「チャートの作成」が開く(ステップ 1/3)
  2. 大目標を入力し、必要なら期限を選ぶ → 「次へ」
- **チュートリアル**: 案内する(目標タブを初めて開いたとき、何をする画面かを伝える)
- **広告**: 出さない(入力の邪魔になるため)
- **受け入れ条件**:
  - [ ] 大目標が空のときは「次へ」を押せない
  - [ ] 期限は空でもよい
- **留意点**: ログインしていなくても使える(端末内に保存し、ログイン後に同期する。SYN-001〜003 と同じ)

### MND-002 大目標を8つの要素に分ける
- **ストーリー**: 目標を立てたい人として、大目標を達成するために必要なことを8つに分けたい。それは、大きすぎる目標を扱える大きさにするため。
- **対象**: 目標を立てたい人
- **優先度**: 高　**状態**: 未実装
- **動作の流れ**:
  1. [チャートの作成 ステップ 2/3] 中心の大目標のまわりの空きマスをタップ → 入力欄が出る
  2. 要素を入力する → マスに入り、要素の色が自動で割り当てられる
  3. 「次へ」 → ステップ 3/3 へ
- **広告**: 出さない
- **受け入れ条件**:

- **動作の流れ**:
  1. [チャート(中心)] 「見直しの履歴」 → 過去の見直しの一覧(日付・決めたことの件数・メモ)
  2. 1つを選ぶ → 見直す前のチャート(当時の進み具合)が見るだけで出る(4-10)
  3. 要素をタップ → その要素の行動目標が並ぶ。今と文言が違うマスには「今は『◯◯』」と出る
  4. 下に「この見直しで決めたこと」「よかったこと」「次に変えること」
- **受け入れ条件**:
  - [ ] 見直しの記録は編集できない
  - [ ] 今のチャートを書き換えても、過去の見直しの記録は変わらない

### MND-031 休止したマスを再開する
- **ストーリー**: 振り返る人として、いったん休んだ行動目標を、また始めたい。それは、余裕ができたときに、元の習慣をそのまま再開するため。
- **対象**: 振り返る人
- **優先度**: 中　**状態**: 未実装
- **動作の流れ**:
  1. [マスの詳細] 休止中のマスに「このマスは休止中です」と「再開する」が出る
  2. 「再開する」 → 休んでいた習慣が記録タブに戻り、進み具合の計算にも戻る
- **受け入れ条件**:
  - [ ] 休止中の日は、進み具合の計算に入らない(要検討: 再開した日から数え直すか)

### 既存の領域への追加(HAB 習慣)

user-stories.md の HAB に足す予定のストーリーです。

### HAB-006 習慣の頻度を決める
- **ストーリー**: 習慣化したい人として、毎日ではない習慣(週2回のジム、月・木のストレッチ)を、その頻度のまま登録したい。それは、毎日やる前提で「できていない」と数えられないようにするため。
- **対象**: 習慣化したい人
- **優先度**: 高　**状態**: 未実装
- **動作の流れ**:
  1. [習慣の登録 / 習慣の編集 / マスの詳細の「＋習慣を作る」] 「頻度」で「毎日 / 週◯回 / 曜日指定」を選ぶ
  2. 「週◯回」→ − ＋ で 1〜6 回を選ぶ。「曜日指定」→ 月〜日のボタンで選ぶ(複数可)
- **受け入れ条件**:
  - [ ] 既存の習慣は「毎日」として扱われる
  - [ ] 「曜日指定」で曜日を1つも選ばないと保存できない
  - [ ] 頻度に応じて、進み具合が計算される(4-6)
- **留意点**: 振り返りタブのダッシュボード(REV-004)、週タブ(WEK)、通知(NTF-001「残りの習慣」)、ウィジェット(WGT)の数え方にも影響する

### HAB-007 頻度に合わせて、記録タブに習慣を出す
- **ストーリー**: 習慣化したい人として、今日やる予定の習慣だけを記録タブで見たい。それは、予定のない習慣が並んで、今日やることが分かりにくくならないため。
- **対象**: 習慣化したい人
- **優先度**: 高　**状態**: 未実装
- **動作の流れ**:
  1. [記録タブ] 「毎日」と「週◯回」の習慣は毎日出る。「週◯回」には「今週 1/2回」のように出る
  2. 「曜日指定」の習慣は、予定の曜日だけ出る。予定のない日は、下に「今日は予定のない習慣」として名前だけ出る
- **受け入れ条件**:
  - [ ] 「週◯回」の習慣は、今週の回数に達したら「達成」と分かる
  - [ ] 予定のない曜日でも、完了にしたいときは完了にできる(要検討)

## 7. データの持ち方(案)

いまの作り(端末内の SQLite → Supabase の `habitas` スキーマに同期)に合わせます。

| テーブル | 主な列 | 説明 |
|---|---|---|
| `mandala_charts` | id, user_id, title(大目標), start_date, end_date, status(active / finished), deleted_at, created_at, updated_at | チャート1枚 |
| `mandala_cells` | id, chart_id, user_id, element_index(0〜7), cell_index(null=要素のマス / 0〜7=行動目標), text, color, **status(active / paused / achieved)**, deleted_at, updated_at | 要素と行動目標のマス。大目標はチャート側に持つ |
| `mandala_cell_events` | id, cell_id, user_id, kind(created / linked / unlinked / lowered / changed / paused / resumed / achieved / removed), note, task_id, created_at | マスの変更の履歴(MND-029)。追記のみ |
| `mandala_reviews` | id, chart_id, user_id, reviewed_at, good_note, next_note, decisions(json), **snapshot(json: 見直す前のチャートの文言・状態・ひもづいた習慣名・進み具合)**, created_at | 見直しの記録(MND-030)。保存後は変更しない |
| `tasks`(既存) | **`mandala_cell_id`**(null 可)、**`mandala_linked_at`**(ひもづけた日)、**`frequency_kind`**(daily / weekly_count / weekdays)、**`frequency_count`**(週◯回)、**`frequency_days`**(曜日。ビットで持つ案)、`ended_at`(終了した日) | 1マスに複数の習慣・タスクがひもづく。1つの習慣・タスクは1マスだけ |

- 進み具合は保存せず、`task_entries`(完了の記録)から計算する。見直しのときだけ `snapshot` に残す(あとで比べるため)
- 頻度を途中で変えたときの数え方(変える前の期間は前の頻度で数えるか)は要検討。簡単にするなら、頻度の変更履歴も持つ
- 同期の方法は既存のテーブルと同じ(updated_at で新しい方を採用、削除は deleted_at)
- **サーバー側の変更は Memory Calendar のリポジトリ** の `supabase/migrations` で行う(`habitas` スキーマはそちらで管理している)。次も必要:
  - RLS(`user_id = auth.uid()`)と権限の付与
  - `delete_app_data('habitas')` で、新しいテーブルも削除する
  - `_app_in_use` の判定に、チャートの有無を加えるか(要検討)

| 段階 | 内容 | 主な場所 |
|---|---|---|
| 1 | サーバーのテーブル(チャート・マス・変更の履歴・見直しの記録、tasks の頻度・ひもづけの列)、RLS、アカウント削除への追加、pgTAP テスト | memory-calendar `supabase/migrations`, `supabase/tests` |

| 3 | 計算ロジック(頻度・予定日・進み具合・見直しの記録の作成)を、画面から独立した関数にしてテスト | life-os `src/lib/mandala/` |
| 4 | 習慣の頻度(登録・編集の画面、記録タブの出し分け、ダッシュボード・週タブ・通知・ウィジェットの数え方) | `RegisterModals`, `TodayView` ほか |
| 5 | 目標タブ(作成、中心・要素・全体、マスの詳細、習慣・タスクの作成とひもづけ、記録タブのチップ) | `src/views/GoalView.tsx` ほか |

| 7 | アカウント削除・チュートリアル・リリースノート・実機確認 | |

### データの持ち方の確定事項
- 頻度: `tasks.frequency_kind`(daily / weekly_count / weekdays)、`frequency_count`(1〜6)、`frequency_days`(ビット: 月=1, 火=2, … 日=64)。変える前の頻度は `frequency_history`(JSON: `[{from, to, kind, count, days}]`)に残し、その期間は前の頻度で数える(決定 #15)
- 予定のない曜日の完了: `task_entries` には記録するが、進み具合では数えない(決定 #16)
- 休止: `mandala_cells.paused_periods`(JSON: `[{from, to}]`)に期間を残し、その日は数えない(決定 #17)
