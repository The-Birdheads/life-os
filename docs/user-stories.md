# ユーザーストーリー(Habitas)

Habitas(コード上の名称は LifeOS)のユーザーストーリーをまとめるファイルです。
書式は `memory-calendar/docs/user-stories.md` に合わせています。**書式・内容とも仮です。** 書きながら使いにくいところを直していきます(書式を変えたときは「更新履歴」に書く)。

用途:
- 何のための機能かを、利用者の視点で一覧できるようにする
- ストーリーと「動作の流れ(どの画面で何をするか)」を見比べて、違和感のある操作や、ずれを見つける
- チュートリアルで何を紹介するか、広告をどこに入れてよいかを決める材料にする
- 実装・テストの「受け入れ条件」の置き場にする(手動テストは `docs/tests/release_test_cases.md`、機能一覧は `docs/features.md` にあり、こちらは利用者の視点の整理)

> **現在は「たたき台」です。** 2026-10-19 時点のコード(`src/`・`ios/`、リリースノート v1.3)から起こしたもので、実機での動作確認はしていません。
> コードだけでは確かめられない箇所は **(要確認)** と書いてあります。見比べて、違和感があれば直してください。

## 1. 書き方のルール

### ID
`領域コード-連番`(3桁)。例: `HAB-001`。一度付けたIDは、ストーリーを消しても使い回さない(欠番はそのままにする)。

### 領域コード
| コード | 領域 |
|---|---|
| ACC | アカウント・ログイン |
| SYN | データの保存・同期 |
| TDY | 記録タブ全般(日付移動・絞り込み・登録ボタン) |
| HAB | 習慣 |
| TSK | タスク(単発・期限つき) |
| ACT | 行動(行動の種類・行動ログ) |
| REV | 振り返り(充実度・メモ・目標・ダッシュボード) |
| WEK | 週タブ(グラフ・表) |
| SET | 設定・メニュー |
| NTF | 通知 |
| WGT | ホーム画面ウィジェット(iOS) |
| ONB | 初回体験(チュートリアル・案内) |
| ADS | 広告 |
| OTH | その他 |

領域が増えたら、この表に足す。

### 項目の意味
| 項目 | 内容 |
|---|---|
| ストーリー | 「〜として、〜したい。それは〜のため」の形で1〜2文 |
| 動作の流れ | **どの画面で何をするか**を、番号つきで書く。「画面 → 操作 → 結果」の順。確定しているものだけ書く(まだ決まっていないものは空欄、または(案)と書く) |
| 対象 | だれの話か(下の「想定ユーザー」の名前) |
| 優先度 | 高 / 中 / 低 |
| 状態 | 実装済み / 一部実装 / 未実装 / 見送り |
| チュートリアル | 案内する(順序つき)/ 案内しない。案内するなら一言で何を伝えるか |
| 広告 | 広告を出してよい / 出さない(理由)/ 該当なし |
| 受け入れ条件 | 「こうなっていればできた」と言える条件。チェックボックスで書く |
| 留意点 | 審査・プライバシー・制約・関連するストーリーのID など |

**必須は「ストーリー」「優先度」「状態」だけ**です。ほかは分かるときだけ書き、迷うものは空欄(または `-`)でよいです。

### 動作の流れの書き方
- 1行に1つの操作。「[画面名] 〜をタップ → 〜が表示される」の形にそろえる。
- 画面名は、実際の画面の名前(タブ名、モーダルの見出しなど)に合わせる。
- ストーリーの「したい」と、流れの最後の結果が、対応しているか見比べる。対応していなければ、どちらかが不適切。
- 実装済みの機能は、現状の操作をそのまま書く。「こうしたい」という変更案は、(案)をつけて分ける。

### 書き方のコツ
- 1つのストーリーは1つの目的だけにする。「〜して、さらに〜できる」は分ける。
- 受け入れ条件は、画面を見て確かめられる言い方にする(例:「一覧の右側に期限が出る」)。
- 実装済みの機能も書く(チュートリアルの材料になるため)。状態を「実装済み」にしておけばよい。

## 2. 想定ユーザー(仮)

| 名前 | 説明 |
|---|---|
| 習慣化したい人 | 運動・読書など、毎日続けたいことがある人。習慣を登録して毎日チェックする |
| やることを整理したい人 | 期限のあるタスクと、毎日の習慣をひとつの画面でまとめて管理したい人 |
| 振り返る人 | 一日の終わりに、充実度とメモを残して、自分の過ごし方を見直したい人 |
| 複数端末で使う人 | ログインして、iPhone と他の端末でデータをそろえたい人 |

(実際の利用者像に合わせて直す。増やしてもよい)

## 3. 画面の名前(流れの中で使う呼び方)

| 呼び方 | 内容 |
|---|---|
| 記録タブ | 下のタブ「記録」。選んだ日の習慣・タスク・行動をカードで管理する。上部に「すべて／習慣／タスク／行動」の切り替えバー |
| 振り返りタブ | 下のタブ「振り返り」。「今日の目標」「今日の振り返り」「ダッシュボード」「実施したこと一覧」が縦に並ぶ |
| 週タブ | 下のタブ「週」。「yyyy年mm月dd日 までの7日間」のグラフと表 |
| ヘッダー | 画面上部の暗い帯。左に「今日」ボタン、中央に ◀ 日付 ▶、右にメニュー(三本線) |
| メニュー | ヘッダー右のハンバーガーボタンで開く。「使い方を見る」「設定」「リリースノート」「ログイン／クラウド同期／アカウント」、バージョン、ログイン状態を表示 |
| ＋ボタン | 記録タブ右下の丸いボタン(FAB)。「習慣の登録」「タスクの登録」「行動の登録」が出る |
| 〇〇の登録 | ＋ボタンから開く全画面のモーダル。習慣・タスクは「表示中／非表示」のサブタブと一覧つき |
| 〇〇の編集 | カードや一覧の項目をタップして開くモーダル。保存・非表示・削除ができる |
| 行動の種類の管理 | 「行動の登録」モーダルの「種類の管理」から開くモーダル |
| ユーザ設定 / 通知設定 | メニューの「設定」の中の2項目。通知設定はアプリ(ネイティブ)でのみ表示 |

## 5. ストーリー一覧

領域ごとに、ID順に並べます。

### ACC アカウント・ログイン

### ACC-001 ログインせずにすぐ使い始める
- **ストーリー**: 初めて使う人として、アカウントを作らずに使い始めたい。それは、まず試してから続けるか決めるため。
- **対象**: 全員
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. アプリを初めて開く → スプラッシュのあと記録タブが開く(端末内に自分専用のデータ領域が自動で作られる)
  2. メニューを開く → 「ステータス: オフラインモード」と表示される
- **広告**: 出してよい
- **受け入れ条件**:
  - [ ] ログインしなくても、習慣・タスク・行動・振り返りがすべて使える
  - [ ] ネットワークがなくても起動できる
- **留意点**: 保存先は端末内の SQLite(SYN-001)。ログインすると中身が引き継がれる(SYN-003)。ログイン画面(`AuthView.tsx`)はコードにあるが、現在は画面から呼ばれていない

### ACC-002 Google でログインする
- **ストーリー**: 複数端末で使いたい人として、Google アカウントでログインしたい。それは、パスワードを増やさずにデータをクラウドに保存するため。
- **対象**: 複数端末で使う人
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. [メニュー] 「ログイン」をタップ → 「Appleでログイン」「Googleでログイン」が開く
  2. 「Googleでログイン」をタップ → アプリ内ブラウザ(Safari)で Google の確認画面が開く
  3. 許可する → アプリに戻り、「データを統合中…」→「クラウドから同期中…」→「同期完了」と出る
  4. [メニュー] 「ログイン中のユーザ」にメールアドレスが表示される
- **受け入れ条件**:
  - [ ] ログイン後、メニューの「ログイン」が「クラウド同期」「アカウント」に変わる
  - [ ] 確認画面を閉じてアプリに戻っても、アプリが壊れない
- **留意点**: アプリへの戻りは `com.morikuma.habitas://login-callback`。Supabase の Redirect URLs にこの値が必要。サーバー(Supabase)に接続できないと、ここでエラーになる(2026-10 に「サーバが見つかりません」が発生。その後、DNS は解消済み)

### ACC-003 Apple でログインする
- **ストーリー**: Apple ID を使いたい人として、Apple でログインしたい。それは、メールアドレスを共有せずに安全にログインするため。
- **対象**: 複数端末で使う人
- **優先度**: 高　**状態**: 実装済み(iOS のみ)
- **動作の流れ**:
  1. [メニュー → ログイン] 「Appleでログイン」をタップ → Apple の確認画面が開く
  2. 許可する → ACC-002 の3以降と同じ
- **受け入れ条件**:
  - [ ] Apple の確認画面を閉じた場合、エラーを出さずに元の画面に戻る
- **留意点**: App Store 審査(他社ログインを出す場合は Apple でサインインも必要)への対応。ボタンは iOS でのみ表示される

### ACC-004 ログアウトする
- **ストーリー**: ログイン中の人として、ログアウトしたい。それは、端末を手放すときや別のアカウントに切り替えるときのため。
- **対象**: 複数端末で使う人
- **優先度**: 中　**状態**: 実装済み
- **動作の流れ**:
  1. [メニュー → アカウント] 「ログアウト」をタップ → 「ログアウトしました」と出て、端末内の自分専用データ(オフラインモード)に切り替わる
- **受け入れ条件**:
  - [ ] ログアウト後も、アプリは落ちずに使える
  - [ ] 再ログインすると、クラウド上のデータが戻る
  - [ ] Memory Calendar に同じアカウントでログインしていても、そちらはログアウトされない(この端末のHabitasだけがログアウトされる)
- **留意点**: ログアウト後に出るデータは、ログイン前に端末内に作ったものになる(ACC-001)。Memory Calendar と共通のアカウントのため、ログアウトは `signOut({ scope: "local" })`(既定の global だと両アプリ・全端末のログインが外れる)

### ACC-005 アカウントを削除する
- **ストーリー**: ユーザーとして、アカウントとデータを削除したい。それは、使わなくなったときに自分のデータを残さないため。
- **対象**: 複数端末で使う人
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. [メニュー → アカウント] 「アカウント削除」をタップ → 「登録済みのすべてのデータが削除され、復元することはできませんがよろしいですか？」が出る
  1'. 確認画面の文言は、Memory Calendar も使っているかで変わる: 使っていない → 「…アカウントも削除されます」/ 使っている → 「Habitasのデータがすべて削除されます。…アカウント自体とMemory Calendarのデータは削除されません」/ 取得できない → 汎用の文言
  2. 「はい」をタップ → (Apple でログインした人は Apple の確認画面が出る。閉じると削除は中止され「アカウントの削除を中止しました」と出る) → 「削除中…」が出て、クラウドのデータ(他のアプリを使っていなければアカウントも)、通知、端末内のデータが削除され、この端末がログアウトされる。完了後に「アカウントを削除しました」または「Habitasのデータを削除しました（アカウントはMemory Calendarで引き続き使えます）」と出る
  3. 「いいえ」をタップ → 何も変わらず閉じる
- **受け入れ条件**:
  - [ ] 削除後、予約済みの通知が来ない
  - [ ] 削除に失敗したら、「削除エラー: …」と画面に出る
- **留意点**: App Store 審査(アカウント削除の提供)に対応。ログインしている人のみに表示される。サーバー側の削除に失敗したときは、端末内のデータは消さず「削除エラー: …」と出す。Apple でログインした人は、削除の前に Apple の確認画面が出て、Apple 側のトークンも取り消す(`revoke-apple-token`、Habitas の client_id で。確認画面を閉じると削除は中止、取り消しに失敗しても削除は続行)。Apple の取り消しはアプリ単位なので、アカウントが残る場合(Memory Calendar も使っている)も、Habitas 分は取り消す。取り消しは iOS のみ

### ACC-006 更新後、ログインし直してデータを引き継ぐ
- **ストーリー**: 以前からHabitasを使っている人として、アプリを更新したあとも、以前のデータをそのまま使い続けたい。それは、ログイン基盤の変更でデータを失わないため。
- **対象**: 複数端末で使う人
- **優先度**: 高　**状態**: 実装済み(実機・ステージングでの確認は未了)
- **動作の流れ**:
  1. 更新前にログインしていた端末で、更新後に初めて起動する → 端末内のデータが、ログイン前の状態(オフラインモード)で見える
  2. 「ログイン方法のお知らせ」が出る → 「以前と同じ方法（GoogleまたはApple）でもう一度ログインしてください」を読んで「OK」をタップ
  3. [メニュー → ログイン] 以前と同じ方法でログインする → サーバーに移行済みのデータと統合され、「同期完了」と出る
- **受け入れ条件**:
  - [ ] 更新前にオフラインで書いて同期できていなかった記録も、ログイン後に残っている
  - [ ] お知らせは、更新前にログインしていた端末にだけ出る(新規インストール・更新前にログアウトしていた端末には出ない)
  - [ ] お知らせは、一度閉じたら繰り返し出ない
- **留意点**: 接続先が Memory Calendar と共通のSupabaseに変わるため、更新後はログイン状態が外れる(`src/lib/legacyAuthMigration.ts`)。端末内データは、旧セッションのユーザーIDからローカルIDへ付け替える。サーバー側のデータ移行スクリプトは、行ID(uuid)を変えずに移すこと(ログイン後の統合で重複させないため)。前回と違う方法でログインすると別のアカウントになり、データは引き継がれない。**端末内のデータの付け替えは補助的な処理**で、iOS では以前、端末内の変更が起動時のスナップショットしか保存されていなかった(`save()` が web のみ。現在は修正済み)ため、引き継げるのは保存済みの分だけ。既存ユーザーのデータの引き継ぎは、旧プロジェクトのサーバーのデータを移行スクリプトで新プロジェクトへ移すことが本命

### SYN データの保存・同期

### SYN-001 ネットワークがなくても記録できる
- **ストーリー**: ユーザーとして、機内モードや電波の弱い場所でも記録したい。それは、記録のためにネットワークを気にしないで済むようにするため。
- **対象**: 全員
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. ネットワークがない状態で、習慣のチェック・タスクの追加・振り返りの保存をする → エラーにならず、画面にすぐ反映される
- **受け入れ条件**:
  - [ ] すべての記録がまず端末内に保存される
- **留意点**: 保存先は端末内 SQLite。ログイン中は、書き込み後に Supabase へも送られる(SYN-002)

### SYN-002 ログイン中、データを自動でクラウドと同期する
- **ストーリー**: 複数端末で使う人として、端末が変わってもデータがそろっていてほしい。それは、機種変更や複数端末でも続けて使うため。
- **対象**: 複数端末で使う人
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. ログインする → 「クラウドから同期中…」のあと「同期完了」と出る
  2. アプリを開き直す・バックグラウンドから戻る → 前回の同期から5分以上たっていれば、画面を止めずに裏で同期する
  3. [メニュー] 「クラウド同期」をタップ → 「同期中…」の画面が出て、手動で同期される
- **受け入れ条件**:
  - [ ] 別の端末で追加した習慣・タスク・行動・振り返りが、同期後に表示される
  - [ ] 同期後、ユーザ設定(ボリューム単位・並び替え)も反映される
  - [ ] 同期に失敗したら、「同期エラー: …」と画面に出る
- **留意点**: 同じデータを2台で同時に編集した場合の優先順位は **(要確認)**(コード上は更新日時で判定している様子)

### SYN-003 ログイン前の記録を、ログイン後に引き継ぐ
- **ストーリー**: 試しに使っていた人として、ログインしたあとも、それまでの記録を残したい。それは、ログインのために記録をなくさないため。
- **対象**: 複数端末で使う人
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. ログインせずに習慣などを記録する(ACC-001)
  2. [メニュー → ログイン] Google または Apple でログインする → 「データを統合中…」と出て、端末内のデータがログインしたアカウントに移る
  3. 「クラウドから同期中…」→「同期完了」
- **受け入れ条件**:
  - [ ] ログイン後も、ログイン前に作った習慣・タスク・記録が見える
- **留意点**: すでにクラウドにデータがあるアカウントでログインした場合の統合結果は **(要確認)**

### TDY 記録タブ全般

### TDY-001 日付を移動して、その日の記録を見る
- **ストーリー**: ユーザーとして、昨日以前の日の記録を見たり、つけ忘れを後から付けたりしたい。それは、記録の抜けをなくすため。
- **対象**: 全員
- **優先度**: 高　**状態**: 実装済み
- **動作の流れ**:
  1. [ヘッダー] ◀ をタップ → 1日前に移る
  2. ▶ をタップ → 1日後に移る(今日のときは押せない)
  3. 日付をタップ → カレンダー(日付選択)が開き、選んだ日に移る(今日より先は選べない)
  4. 「今日」をタップ → 今日に戻る(すでに今日のときは薄く表示され、押せない)
- **受け入れ条件**:
  - [ ] 選んだ日の習慣チェック・行動ログが表示される
  - [ ] 記録・振り返り・週の3つのタブで、日付が共通している
- **留意点**: 日付は日本時間(JST)で数える

### TDY-002 習慣・タスク・行動を絞り込んで見る
- **ストーリー**: ユーザーとして、いま見たい種類だけを表示したい。それは、項目が増えても探しやすくするため。
- **対象**: 全員
- **優先度**: 中　**状態**: 実装済み
- **動作の流れ**:
  1. [記録タブ／振り返りタブ] 上のバーで「すべて」「習慣」「タスク」「行動」をタップ → 選んだ種類のカードだけが出る

### HAB-003 習慣を編集する・削除する

- **留意点**: 削除は元に戻せない。過去の完了記録への影響は **(要確認)**(コード上は論理削除)

  - [ ] 保存後に開き直しても、充実度とメモが残っている
  - [ ] 充実度の範囲(1〜100)の外の値は保存されない
- **留意点**: 充実度は週タブのグラフ・表で使う(WEK-001、WEK-002)

### REV-002 明日の目標を書く

  - [ ] 達成度は、週タブの表の「目標」列で見られる(WEK-002)

### REV-004 その日にやったことをダッシュボードで確認する
- **ストーリー**: 振り返る人として、その日に習慣・タスク・行動をいくつ、どれくらいの量やったかを一目で知りたい。それは、振り返りを数字にもとづいて書くため。

  - [ ] 日付を移動すると、その日の数字に変わる
- **留意点**: Vol(ボリューム)は、ユーザ設定の単位(15分・30分・1時間)に換算して見られる(SET-001)

### REV-005 実施したことを一覧で確認する

### SET-002 習慣・タスクの並び順を決める

- **受け入れ条件**:
  - [ ] 記録タブ・振り返りタブの両方で、同じ並び順になる

### SET-003 通知の時刻とタイミングを決める

  3. タスクの期限前は、「3日前」「2日前」「1日前」から複数選べる
  4. 「保存する」 → 「通知設定を保存しました」
